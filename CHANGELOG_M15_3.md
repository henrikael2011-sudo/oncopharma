# M15.3 — Cuidador (R4 / P-R4)

- **Convite somente pelo paciente:** "Cuidador e privacidade" cria um código de uso único (12 símbolos sem caracteres ambíguos ≈ 60 bits, formato XXXX-XXXX-XXXX), válido por **72 h**; o banco guarda só o hash SHA-256. Prazo do acesso escolhido pelo paciente: 30, 60 ou **90 dias (máximo, garantido por CHECK)**. Até 3 convites pendentes; convite pode ser cancelado.
- **Aceite pelo cuidador:** a conta sem vínculo vê "Seu acesso ainda não foi liberado" + "Sou cuidador e recebi um código" com aceite de termos. Código errado/expirado/usado ⇒ 403 genérico, **recusa auditada** (`care.caregiver.invite.rejected`) em transação própria. Paciente não pode usar o próprio código; uma conta de cuidador acompanha um paciente ativo por vez (P-R4b).
- **Tudo desligado por padrão:** o vínculo nasce com `scopes='{}'`. Escopos fechados: `ver_jornada`, `ver_medicamentos`, `registrar_sintoma`, ligados/desligados pelo paciente. A API aplica `CareController.need()` em cada rota; o menu do cuidador mostra só o liberado; gestão de cuidadores, consentimento, preferências e adesão são exclusivos do paciente.
- **Revogação imediata e definitiva:** "Encerrar acesso agora" ⇒ próxima requisição do cuidador já recebe 403; trigger impede reativar ou alterar um vínculo revogado; sem DELETE (histórico preservado).
- **Histórico de acessos visível ao paciente:** tabela `caregiver_access_events` (insert-only) sem conceder leitura de `audit_events` à aplicação; toda ação do cuidador também vai para `audit_events` com `actor_role=caregiver`. Relatos feitos pelo cuidador ficam marcados `details.reported_by='caregiver'` com o sujeito do cuidador.
- **Banco — migração 0010:** `caregiver_invites`, `caregiver_links`, `caregiver_access_events`, `patient_care_preferences.display_name`; RLS FORCE por organização com `nullif`; GRANT de UPDATE só em colunas de ciclo de vida.
- **Testes:** `tests/m153-caregiver.mjs` (código, hash, escopos, gestão só do paciente, BFF), `tests/m153-db-caregiver.integration.mjs` (72 h, 90 dias, hash obrigatório, escopos fechados, revogação definitiva, sem DELETE, isolamento), E2E 07d (convite → código errado auditado → aceite → nada visível → API 403 → paciente libera jornada/sintoma → cuidador vê/registra → adesão negada → histórico → revogação imediata; axe).
